# Dexxer

A private perpetual DEX for Solana Seeker. A position is visible only to its owner.

## Architecture (decisions made 18.09.2026, do not revisit without a reason)
- Option A: our own perp core on the MagicBlock template, NOT an omnibus over Jupiter, NOT a Percolator fork
- A position is a **delegated** PDA in PER with `EphemeralPermission { is_private, members: [owner, session, crank] }`; zero commits to L1 before close. L1 shows only an account under the Delegation Program with its onboarding bytes **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**
- No account with position fields is committed before close: `MarketRisk`, `DisclosureQueue` — never; `UserAccount` — only `free_margin`/`locked_margin` **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**
- All **per-user** accounts (`UserAccount`/`Position`/`DisclosureQueue`) are permissioned `[owner, session, crank]`. **Week 4 fact (risk #24 closed, 23.09.2026):** `MarketRisk`+`PoolLive` are permissioned `[crank, admin]` (`init_market_permissions`); `Pool` stays public, but is now only a coarsened snapshot (`SNAPSHOT_STEP`, filled only by `commit_aggregate`) — the live counters that used to live in the public `Pool`/`MarketRisk` in the ER (week 3, 22.09.2026, risk #24: `delegate_pool`/`delegate_market` do not create an `EphemeralPermission`) are now in the private `PoolLive`. The public aggregate reaches the world on L1 only through the 5-min commit of `Pool` (+`BalancesRoot`, week 3) **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**
- Margin is accounting in the private `UserAccount`/`Position`, not tokens. The user's eATA exists only for deposit/withdrawal; open/close do not touch token accounts. **Margin mode is Isolated only (decision 04.10.2026):** collateral is on the `PositionSlot`, liquidation is per slot, a task per (trader, market) pair; there is no Isolated/Cross switch and none is planned before mainnet — Cross belongs to order-book exchanges with shared collateral (Drift, Zeta), perps with a pool counterparty (Jupiter Perps, Flash Trade) live on Isolated; the ticket shows a static "Isolated" label (spec §1.1, backlog 6.B)
- Privacy is MagicBlock PER (Intel TDX), not ZK and not FHE. The claim: from trackers, copy bots and from us; not from Intel and not from the operator
- Custody is Ephemeral SPL Token (Global Vault on L1 + pool eATA in the ER)
- Prices are Pyth Lazer through the MagicBlock Pricing Oracle, mark = EMA over index, liquidation by mark
- ~~Disclosure — commit-then-reveal~~ **cancelled 30.09.2026 (spec §2.9):** trades are not disclosed; only the coarsened `Pool` and `BalancesRoot` are public; a trader's own history is a private ring of 16 records in `Positions`
- Devnet-first: `devnet-tee-as.magicblock.app`, our own `dUSDC` faucet mint, the protocol funds the pool
- There is no backend that sees private data, and there will not be one. The crank is in the ER (scheduler); the fallback script outside is the only privileged service (a permission member) and stores no state. **Servers read only public L1/ER accounts and the oracle** (decision 22.09.2026): a stateless indexer for prices/charts, `Pool`/`BalancesRoot` snapshots, the L1 `Disclosure` feed and push is allowed; no service except the crank holds owner/session tokens (the week-6 relayer API SIWS sessions are **not** such tokens: they open only `/sponsor`/`/nonce`, not the TEE, and the DB holds only a `sha256`, spec §2.7); private state is read only by the client through the owner TEE (`accountSubscribe` instead of polling — week 4) **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**

## Rules
- Anchor 1.0.2, Solana 3.1.9, Rust 1.89, `ephemeral-rollups-sdk` 0.16.2 (`anchor`, `access-control`), TS SDK 0.17, `@solana/web3.js` v1 (not kit)
- Rounding is always in the pool's favour; all math is in `math.rs`, `u128` intermediates, `checked_*`
- **Privacy = a read filter in the TEE/QFS, NOT encryption** (as long as MagicBlock `onchain-privacy`/`local-development`). L1 has no filter → **a raw private (permissioned) account is never committed to L1 as is** — that would make the bytes public; the TEE does not let such a commit through (risk №13, confirmed by mechanism and in practice — `undelegate_user` also failed on this, week 3, ruling 10, below). Everything that must reach L1 goes out only through a separate **public** derived account (`Pool` aggregate, `BalancesRoot`, `Commitment`/`Disclosure` — week 3). The trustless exit is on the public `BalancesRoot` receipt (no L1 claim, MVP), not on `UserAccount` commits **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**
- The aggregate is committed at a fixed interval as a batch, never per event and never on every action. **`commit_aggregate` is the single 5-min bundle: `commit(&[Pool, BalancesRoot])` + post-commit actions from `DisclosureQueue`** (`write_commitment`/`write_disclosure`, week 3; the source is the queue, not `Position`, week 5, see "Week 5 rules") — **it is called every cycle regardless of whether there are actions** (fix round 1, week-3 Task 7): the fixed commit of `Pool`+`BalancesRoot` does not depend on whether there is anything in `remaining_accounts`. The program CEILING is `MAX_ACTIONS_PER_COMMIT = 8` (week 5, was 4), and the actual bundle budget is passed by the client as the argument `commit_aggregate(max_actions)` (week-5 final review, C1) — **the live relayer default is `COMMIT_MAX_ACTIONS = 4`**, because the real MagicBlock bridge rejects 8 real actions (measured in week 5). `withdraw` contains a commit intent for `UserAccount`, but on devnet-tee it **does not reach L1 by design** (see the privacy rule above) — the money moves correctly (ER accounting + SPL), only the L1 snapshot of `UserAccount` stays stale; this is not a bug to patch but a signal to build the exit on the public root (implemented in week 3, `BalancesRoot`) **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**
- Oracle: on every read — feed id, `posted_slot > 0`, staleness, confidence, deviation. Stale → skip liquidations, do not liquidate at an old price
- Do not use `init_if_needed`; `write_commitment` checks the escrow signer **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**
- Solana MCP `program_autofixer` on every program change before commit
- Skill `magicblock` — for ER/PER/eSPL/oracle/session keys; `solana-dev` — for Anchor/clients/tests

- **`Commitment`/`Disclosure` PDAs are seeded by the commitment hash** (`[SEED, hash]`), not `UserAccount.nonce` — a per-user nonce collides between different traders on their first close (ruling 9, found on devnet). `nonce` stays a field of `DisclosureArgs`/`ClosedRecord`, just not a seed **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**

- **`BalancesRoot` is `#[account(zero_copy)] #[repr(C)]`, NOT Borsh** — by-value Borsh deserialization of a 2 KiB account (`leaves: [[u8;32];64]`) blew the SBF stack (LiteSVM `Access violation in stack frame 3`); layout `root_slot:u64 | leaves:[[u8;32];64] | version:u8 | filled:u8 | bump:u8 | _pad:[u8;5]`, access through `AccountLoader`, not `Account`

## Week 4 rules (22–23.09.2026)

- **`PoolLive` is the private working aggregate, `Pool` is only a coarsened snapshot.** All trading/money instructions (`open/close/resize`, `deposit`/`withdraw`, `crank_tick`) write **only `PoolLive`**; `Pool` is filled **only by `commit_aggregate`**, coarsened to `SNAPSHOT_STEP = 100_000_000` (100 dUSDC): assets (`capital_total`/`protocol_liquidity`/`insurance`) — down (floor), liabilities (`locked_total`/`bad_debt_total`) — up (ceil), conservative for a reader of solvency
- **`MarketRisk`+`PoolLive` are permissioned `[crank, admin]`** (`init_market_permissions`, ER, risk #24 closed). The rent surplus for their self-funding CPI goes through a **base-layer eSPL delegated-lamports transfer** (`lamportsDelegatedTransferIx(admin, dest, lamports, salt)` to an already delegated PDA), NOT through the ER instruction itself — six in-tx mechanisms (self-funding, CPI payer, caller-side transfer, etc.) were rejected with different errors (`InsufficientFundsForRent`/`InvalidWritableAccount`/`InvalidAccountForFee`/`UnbalancedInstruction`); the sanctioned path worked on the first try
- **`init_pool_live` reads `Pool` as an `UncheckedAccount`**, not `Account<Pool>` — the `Pool` already delegated on devnet (weeks 1–3) is owned by the Delegation Program, `Account<'info, Pool>` would reject it with `AccountOwnedByWrongProgram`; a manual `Pool::try_deserialize` (discriminator, no owner check)
- **`services/relayer`** (Express + `ws` + Railway Postgres) is the only privileged service: it holds only `crank`/`fee_payer` (env, base58), reads only public accounts + the oracle (TEE without a token for the oracle — the feed is public even behind the TEE endpoint). Three loops: crank (`crank_tick` 1 s, disclosure/root cycles), public-data indexer (REST+WS: `/mark`, `/prices`, `/pool/latest`, `/disclosures`, `/root/latest`), `POST /sponsor` **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**
- **`/sponsor` whitelist** — `faucet_init`/`init_user`/`delegate_user` + eSPL `delegateSpl`, a role check of the `payer`/`owner` position by the IDL/SDK account order (`checkInstruction`/`IxShape`, not only the discriminator — no other key may equal `fee_payer`), an atomic rate limit (`SponsorStore.reserve`, `ON CONFLICT ... DO NOTHING RETURNING`, 6 slots/owner/window)
- **`FaucetInit`/`InitUser` have a separate `payer: Signer`** (rent is paid by `fee_payer`, ATA rent by the owner). Delegation (`delegate_user`'s own CPI) stays owner-paid — ≈0.004 SOL minimum, not zero. **The ER leg (permissions+session) cannot be sponsored** — the TEE rejects someone else's `fee_payer` as the payer of an ER tx it did not initiate (`InvalidAccountForFee`)
- **Scheduler `i64::MAX` — applied on the live schedule, a mark backstop, NOT a liquidation backstop.** `ScheduleCrank` registers the task without `remaining_accounts` (the accounts are fixed forever at registration) — a scheduled tick moves only `Market.mark`/EMA and never liquidates (measured: `Position.liq_ticks` stayed `0` over 90 seconds of polling for a force-liquidatable position with the relayer crank off). `crank-fallback`/`services/relayer` stays mandatory for liquidations regardless of `iterations`
- **UI — only tokens from `docs/design/tokens.json`**, no hard-coded hex in components (`app/src/theme/tokens.ts` is generated by `npm run gen:tokens`, regenerated deterministically)
- **`useLiveAccount` — `accountSubscribe`-first, poll fallback.** The TEE sends a notification on every ER slot regardless of whether the account bytes changed — the raw bytes are compared (`Buffer.equals`) before `decode`/`setState`; the unconditional poll became fallback-only (2 s, only if no push arrived within 5 s or the subscription failed synchronously)
- ~~**Emulator/AVD smoke is the user's job, agents do not run it**~~ **lifted 23.09.2026 for week 5+**: the user removed the restriction — agents may start the AVD/app for verification; the agent still leaves the checklist for a live run with a real wallet (Phantom/Seeker) to the user and does not imitate it itself (rule below, "Week 5 rules")

## Week 5 rules (23–24.09.2026)

It is cancelled in `close_position`/a full `decrease_position`/`undelegate_user`; cancelling an unknown `task_id` is a measured safe no-op, not an error. The task registry is invisible outside the TEE. **M-G′ PASS: liquidation without the relayer in 6.97 s.** The `liq_hysteresis_ticks` default 2 → 3 — there are now two independent sources of ticks (`crank_tick` and `liquidation_check`), to avoid double counting **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**

The orphan signal of `close_orphan_queue` (ER, crank) — `UserAccount` missing/foreign **OR** present with `exited == true` (the first formula without the third branch was measured always false on devnet-tee — the ER returns an undelegated account as a clone of the base). `close_exited_user` (base, `fee_payer`) closes all three PDAs together — it replaces the brief's variant `close_queue_l1` (which "bricked" the owner without the `exited` gate) **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**
- **`DelegateUser.payer`** is separate from `owner` — the rent of the three delegations is now on `fee_payer`; `/sponsor` whitelist `{faucet_init, init_user, init_user_reuse_queue, delegate_user}`, all `{ownerIdx:0, payerIdx:1}`; ATA `{payerIdx:0=fee_payer, ownerIdx:2=owner signer}`. **M-I PASS: the full cycle on 0-SOL wallets, including the ER leg (0 lamports)** **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**
- **`commit_aggregate(max_actions: u8)` — the action budget per bundle is chosen by the CLIENT** (week-5 final review, C1; upgrade #3 `eXAtUAVt…`, 24.09.2026). The program clamps to `[1, MAX_ACTIONS_PER_COMMIT]`; `MAX_ACTIONS_PER_COMMIT = 8` stays a hard CEILING, not the number of actions in a bundle. Measured on the real action shape: **8 real actions = bridge `0xA0000002` FAIL, 4 = PASS** (week 5, Task 7). Before this argument, `room` was taken straight from the constant — **one** queue with a full ring always emitted all 8 actions regardless of env, and that is exactly what made a full ring undrainable forever (the position neither closes, `QueueFull`, nor is liquidated). This is the full mechanism of the "poisoned queue" — not the action content and not bridge overload **[Outdated since 30.09.2026: see "Week 6 rules: position slots"]**

## Orders v2 rules (04.10.2026, branch `feat/orders-v2`; tests only — NOT measured on devnet; full description — spec `2026-10-03-conditional-orders-design.md`)
- **Layout (in one upgrade):** `OrderSlot` 88 → **96 B** (`limit` between `sl` and `kind`), the tail 704 → **768 B**, `SPACE_WITH_ORDERS` 3888 → **3952**; `UserAccount.order_reserved: u64` taken from `_reserved` (32 → 24 B, the size 207 is unchanged). An account ≥ 3952 B has the tail; 3888 B (the previous tail) is read as an account WITHOUT a tail (`OrdersUnsupported`, re-onboarding). The TS decoders accept 3184/3888/3952
- **Stop-limit:** a `Stop` with `limit != 0` fills only within the limit (`within_limit`), outside it the order waits with its reserve. **Margin reserve:** `place_order` of an entry order moves `margin` from `free_margin` to `order_reserved`; cancel/execution/reset/siblings return it (`UserAccount::reserve/release`, `clear_entry` returns the amount). The opening fee is NOT reserved (it is taken at execution; an order that cannot pay it is dropped). The reserve is part of the pool invariant (`Σ free + Σ order_reserved + Σ open margin`), and blocks `withdraw` (which sees only `free`) and `undelegate_user`/`close_exited_user` (`BalanceNotZero`)
- **Partial TP/SL:** `size > 0` in a reduce-only order = close a part through the shared `decrease_core` (like `decrease_position`; all checks before the first write — the executor swallows the error); `size == 0` — the whole position, one per type and market; there may be several partial ones, only the same (type, trigger, size) is replaced. The remainder ≥ `min_size`

(2) **An order error never fails the tick:** `crank_tick` and `liquidation_check` log `orders: skipped (error)` instead of `?` — otherwise one trader's order would abort the whole crank batch, and in the scheduler would roll back the liquidation hysteresis; a full exit that the pool cannot pay stays pending. (3) **`undelegate_user` zeroes all bytes after `Positions::SPACE`** regardless of the tail length — the program does not read a 3888 B account (the previous tail) as orders, but the old bytes must not reach L1. (4) **App: `lib/decimal.ts` `parseAmount`** — a filled field is a number > 0 (comma or dot) or a form error, never a silent 0 (0 for the program = "the whole position" / "no limit"); do not use `Number(text) || 0` in order fields. ## Market selector rules (05.10.2026, spec `2026-10-05-market-selector-design.md`)
- The Trade header is a market button (`AssetIcon` + `SYMBOL-PERP ▾` + max leverage) that opens the modal route `/markets`. There are no favourite chips under it (removed 05.10.2026): favourites live only as the ★ tab of the markets screen. `MarketPicker` is gone.
- The markets screen never fetches per market: prices come from the WS mark cache (`useQueries` with `enabled: false`), 24h change from `GET /tickers` (one answer for every client, cached 30 s on the relayer, `TICKERS_CACHE_MS`). Favourites (`dexxer.favorites`) and sort (`dexxer.marketsSort`) stay on the device; a storage read error is never written back.
- `GET /markets` carries `name` from `services/relayer/assets/assets.json` (`null` when absent). A new market needs an `assets.json` entry for its name and an official brand SVG in `AssetIcon` (`BRAND_ICON_SYMBOLS` + `GLYPHS`; otherwise a letter avatar — never a traced logo). SOL, BTC, ETH, HYPE and ZEC ship brand marks (sources listed in `AssetIcon.tsx`).
- A row in the markets list is two sibling buttons (row, ★): a nested `Pressable` inside an accessible one is invisible to TalkBack on Android.
- The ticket's submit button always names the market (`submitLabel`).
