# Dexxer

Приватний perpetual DEX для Solana Seeker. Позиція видима лише власнику.

## Архітектура (рішення прийняті 18.09.2026, не переглядати без причини)
- Опція A: власне перп-ядро на шаблоні MagicBlock, НЕ омнібус над Jupiter, НЕ форк Percolator
- Позиція — **делегований** PDA в PER з `EphemeralPermission { is_private, members: [owner, session, crank] }`; нуль комітів на L1 до закриття. На L1 видно лише акаунт під Delegation Program з байтами онбордингу **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- Жоден акаунт із полями позиції не комітиться до закриття: `MarketRisk`, `DisclosureQueue` — ніколи; `UserAccount` — лише `free_margin`/`locked_margin` **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- Усі **per-user** акаунти (`UserAccount`/`Position`/`DisclosureQueue`) — permissioned `[owner, session, crank]`. **Week 4 факт (ризик #24 закрито, 23.09.2026):** `MarketRisk`+`PoolLive` — permissioned `[crank, admin]` (`init_market_permissions`); `Pool` лишається публічним, але тепер лише огрублений знімок (`SNAPSHOT_STEP`, заповнюється лише `commit_aggregate`) — живі лічильники, які раніше жили в публічному `Pool`/`MarketRisk` в ER (тиждень 3, 22.09.2026, ризик #24: `delegate_pool`/`delegate_market` не створюють `EphemeralPermission`), тепер у приватному `PoolLive`. Публічний агрегат виходить у світ на L1 тільки через 5-хв коміт `Pool`(+`BalancesRoot`, week 3) **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- Маржа — облік у приватних `UserAccount`/`Position`, не токени. eATA юзера існує лише на депозит/вивід; open/close не торкаються токен-акаунтів
- Приватність — MagicBlock PER (Intel TDX), не ZK і не FHE. Формулювання: від трекерів, копі-ботів і від нас; не від Intel і не від оператора
- Кастоді — Ephemeral SPL Token (Global Vault на L1 + pool eATA в ER)
- Ціни — Pyth Lazer через MagicBlock Pricing Oracle, mark = EMA над index, ліквідація за mark
- ~~Розкриття — commit-then-reveal~~ **скасовано 30.09.2026 (spec §2.9):** угоди не розкриваються; публічні лише огрублений `Pool` і `BalancesRoot`; власна історія трейдера — приватне кільце на 16 записів у `Positions`
- Devnet-first: `devnet-tee-as.magicblock.app`, власний `dUSDC` faucet-мінт, пул фондує протокол
- Бекенду, що бачить приватні дані, нема і не буде. Crank — у ER (scheduler), fallback-скрипт зовні — єдиний привілейований сервіс (permission-член), стану не зберігає. **Сервери читають лише публічні акаунти L1/ER і оракул** (рішення 22.09.2026): stateless-індексер для цін/графіків, `Pool`/`BalancesRoot`-снапшотів, L1 `Disclosure`-ленти, push — допустимий; жоден сервіс, крім crank-а, не тримає owner/session-токенів (SIWS-сесії API relayer-а тижня 6 — **не** такі токени: відкривають лише `/sponsor`/`/nonce`, не TEE, у БД лише `sha256`, spec §2.7); приватний стан читає лише клієнт через owner-TEE (`accountSubscribe` замість polling — тиждень 4) **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**

## Правила
- Anchor 1.0.2, Solana 3.1.9, Rust 1.89, `ephemeral-rollups-sdk` 0.16.2 (`anchor`, `access-control`), TS SDK 0.17, `@solana/web3.js` v1 (не kit)
- Округлення — завжди на користь пулу; вся математика в `math.rs`, `u128` проміжні, `checked_*`
- **Приватність = фільтр читання в TEE/QFS, НЕ шифрування** (доки MagicBlock `onchain-privacy`/`local-development`). На L1 фільтра немає → **сирий приватний (permissioned) акаунт ніколи не комітиться на L1 як є** — це зробило б байти публічними; TEE такий коміт не пропускає (ризик №13, підтверджено механізмом і практично — `undelegate_user` теж впала на цьому, week 3, рулінг 10, нижче). Усе, що має вийти на L1, виходить лише через окремий **публічний** похідний акаунт (`Pool`-агрегат, `BalancesRoot`, `Commitment`/`Disclosure` — week 3). Trustless-exit — на публічному `BalancesRoot`-квитанції (без L1-claim, MVP), не на комітах `UserAccount` **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- Коміт агрегату — фіксованим інтервалом батчем, ніколи подієво і ніколи на кожну дію. **`commit_aggregate` — єдиний 5-хв bundle: `commit(&[Pool, BalancesRoot])` + post-commit дії з `DisclosureQueue`** (`write_commitment`/`write_disclosure`, week 3; джерело — черга, не `Position`, week 5, див. «Правила тижня 5») — **викликається щоцикл незалежно від наявності дій** (fix round 1, Task 7 тижня 3): фіксований коміт `Pool`+`BalancesRoot` не залежить від того, чи є щось у `remaining_accounts`. Програмна СТЕЛЯ `MAX_ACTIONS_PER_COMMIT = 8` (week 5, було 4), а фактичний бюджет бандла передає клієнт аргументом `commit_aggregate(max_actions)` (фінальне ревʼю week 5, C1) — **живий relayer-дефолт `COMMIT_MAX_ACTIONS = 4`**, бо реальний бридж MagicBlock відхиляє 8 реальних дій (виміряно week 5). `withdraw` містить commit-intent для `UserAccount`, але на devnet-tee він **не долітає до L1 за задумом** (див. правило приватності вище) — гроші рухаються коректно (ER-облік + SPL), лише L1-снапшот `UserAccount` лишається застарілим; це не баг для латання, а сигнал будувати exit на публічному root (реалізовано тижнем 3, `BalancesRoot`) **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- Оракул: на кожне читання — feed id, `posted_slot > 0`, staleness, confidence, deviation. Stale → скіп ліквідацій, не ліквідація за старою ціною
- `init_if_needed` не використовувати; `write_commitment` перевіряє escrow-підписанта **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**

## Правила тижня 3 (13F-розкриття, `BalancesRoot`, вихід — 21–22.09.2026)

Golden vectors спільні для Rust-юніт-тесту й TS (`tests/er/lib/hashes.selftest.ts`, `app/src/lib/hashes.ts`) — пінять байтовий лейаут між мовами

## Правила тижня 6: мульти-маркет, програма (28.09.2026, spec §2.8)
- **Ринок = символ.** `init_market(symbol: [u8; 8], …)`/`delegate_market(symbol)`, сіди `[MARKET_SEED, symbol]`; символ — 1–8 байт `A-Z0-9`, доповнений нулями (`validate_symbol`, інакше `InvalidSymbol`) — це PDA-сід, тож малі літери чи байт після нулів дали б другий акаунт «того самого» ринку. PDA SOL (`"SOL\0…"`) незмінний. `max_position` — **номінал у USD (1e6)**, не розмір: однакова доларова стеля для всіх ринків — те саме значення, що в SOL, НЕ масштабувати ціною; `min_size` — розмір, свій на ринок
- **Позиція на КОЖНОМУ ринку, створена разом, ніколи при угоді** (приватність L1: сід `[position, owner, market]` видно на L1, створення при першій угоді розкрило б вибір ринку й час). SOL-позицію створює `init_user`; інші — `init_position(symbol)` + `delegate_position(symbol)` (L1, `owner` + спонсорований `payer`, рента ≈0.00274 SOL/ринок) → `init_position_permission()` (ER, власник або живий сесійний ключ). **≤ 3 ринки на спонсоровану L1-tx** (nonce + 2 CB: N=3 — 1164 B) **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- **`set_session` — пари `[position, position_permission]` інших ринків у `remaining_accounts`**, кожна перевіряється вручну (власник програми, дискримінатор `Position`, `position.owner == owner`, permission = PDA від ключа позиції). Без пар — поведінка як раніше (лише SOL) **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- **Вихід:** гейт `undelegate_user` за маржею (`free == 0 && locked == 0`) уже покриває всі ринки — окремої перевірки позицій не треба. Додаткові позиції виходять через `undelegate_position()` (ER, власник будь-коли; **crank — лише коли власник пішов**; сесія — ні; позиція `Empty`, без скрабу — `finalize_close` уже обнулила) і `close_exited_position()` (L1, `fee_payer`) **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- **SOL-позиція живе й помирає з `UserAccount`:** `init_user`/`init_user_reuse_queue` пінять її до SOL-ринку, тому `undelegate_user`/`close_exited_user` приймають **лише** SOL-позицію, а `delegate_position`/`undelegate_position`/`close_exited_position` — **лише** не-SOL (`PrimaryPositionMismatch`, 6048). Закрита окремо SOL-позиція назавжди ламала б повторний онбординг (reuse її не знайде, `init_user` впреться в наявний `UserAccount`) — janitor ніколи не шле SOL-позицію в per-market інструкції **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- **`user_has_left` консервативний:** `UserAccount` відсутній або під програмою з `exited`. Делегований (власник — Delegation Program) чи чужий — активний власник, НЕ пішов. `require_user_active` (гейт `init_position`/`delegate_position`): делегований — активний; під програмою — читається `exited` **[Застаріло з 30.09.2026: див. «Правила тижня 6: позиції-слоти»]**
- **Регенерація IDL без `anchor-cli`** (його `[toolchain] solana_version` перемикає глобальну Solana): викликати `anchor_lang_idl::build::IdlBuilder` 0.1.4 з окремого bin, **абсолютний** шлях до програми, свіжий `CARGO_TARGET_DIR` на кожен checkout; канонічний IDL — `idl/dexxer_core.json` (з 30.09.2026; раніше `app/src/idl/`), без кінцевого `\n` (CI робить `cmp` з виходом `anchor build`); генератор — `tools/idlgen` (команда в його README)
